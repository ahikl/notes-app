## 1. 加密算法分析

### 1.1 支持的加密算法

项目支持以下AES加密算法（定义于 `CryptoService.ts`）：

```typescript
const SUPPORTED_ALGORITHMS = [
  'aes-256-cbc', // CBC模式（默认）
  'aes-192-cbc',
  'aes-128-cbc',
  'aes-256-gcm', // GCM模式（认证加密）
  'aes-192-gcm',
  'aes-128-gcm',
];
```

### 1.2 默认配置

| 配置项        | 默认值          | 说明                    |
| ------------- | --------------- | ----------------------- |
| 默认算法      | `aes-256-gcm`   | 主要加密方法使用GCM模式 |
| 默认密钥长度  | 32字节（256位） | 符合AES-256标准         |
| GCM模式IV长度 | 12字节          | GCM模式推荐值           |
| CBC模式IV长度 | 16字节          | CBC标准要求             |

### 1.3 算法选择的安全性考量

#### GCM模式（推荐）

- **认证加密**：提供机密性和完整性双重保护
- **Auth Tag**：128位认证标签防止数据篡改
- **性能优势**：支持并行加密，适合移动设备

#### CBC模式（兼容）

- **传统模式**：广泛支持，兼容性好
- **需要填充**：使用PKCS7填充处理非块大小倍数的数据
- **无内置认证**：需额外机制验证数据完整性

### 1.4 密钥长度验证

```typescript
private static isValidKeyLength(length: number, algorithm: string): boolean {
  // AES-256 系列（CBC 和 GCM）
  if (algorithm === 'aes-256-cbc' || algorithm === 'aes-256-gcm') return length === 32;
  // AES-192 系列
  if (algorithm === 'aes-192-cbc' || algorithm === 'aes-192-gcm') return length === 24;
  // AES-128 系列
  if (algorithm === 'aes-128-cbc' || algorithm === 'aes-128-gcm') return length === 16;
  return false;
}
```

## 2. 密钥管理机制

### 2.1 密钥生成过程

#### 随机密钥生成

```typescript
static generateRandomKey(length: number = 32): Buffer {
  // 验证密钥长度必须是16、24或32字节
  if (length !== 16 && length !== 24 && length !== 32) {
    throw new CryptoError('密钥长度必须是16、24或32字节', CryptoErrorCode.INVALID_KEY);
  }
  // 使用react-native-quick-crypto生成随机字节
  return Buffer.from(crypto.randomBytes(length));
}
```

#### 随机性保证

- 使用 `react-native-quick-crypto` 的 `randomBytes` 方法
- 底层依赖操作系统提供的安全随机数生成器（/dev/urandom 或 CryptGenRandom）
- 符合密码学安全伪随机数生成器（CSPRNG）要求

static async storeKey(keyId: string, keyBase64: string, metadata: KeyMetadata): Promise<void> {
  // 验证密钥格式和长度
  if (!CryptoService.isValidBase64(keyBase64)) {
    throw new KeyStorageError('密钥必须是有效的base64编码', KeyStorageErrorCode.INVALID_KEY);
  }

  const keyBuffer = Buffer.from(keyBase64, 'base64');
  if (keyBuffer.length !== 16 && keyBuffer.length !== 24 && keyBuffer.length !== 32) {
    throw new KeyStorageError(
      `密钥长度${keyBuffer.length}字节无效，必须是16、24或32字节`,
      KeyStorageErrorCode.INVALID_KEY,
    );
  }

  const storageKey = `${KEY_STORAGE_PREFIX}${keyId}`;
  const storedItem: StoredKeyItem = { key: keyBase64, metadata };

  // 存储到SecureStore
  await SecureStore.setItemAsync(storageKey, JSON.stringify(storedItem));

  // 更新元数据索引
  await this.updateMetadataIndex(keyId, metadata);
}

### 2.4 密钥格式验证

```typescript
// Base64格式验证
static isValidBase64(str: string): boolean {
  if (!str || typeof str !== 'string') return false;
  try {
    const decoded = Buffer.from(str, 'base64');
    return decoded.toString('base64') === str;
  } catch {
    return false;
  }
}

// 密钥格式验证
export const validateKeyFormat = (keyBase64: string): boolean => {
  if (!keyBase64 || typeof keyBase64 !== 'string') return false;
  if (!isValidBase64(keyBase64)) return false;

  try {
    const decoded = Buffer.from(keyBase64, 'base64');
    // AES密钥长度必须是16、24或32字节
    return decoded.length === 16 || decoded.length === 24 || decoded.length === 32;
  } catch {
    return false;
  }
};
```

### 2.5 安全比较机制（防时序攻击）

```typescript
export const secureCompareKeys = (key1: string, key2: string): boolean => {
  if (typeof key1 !== 'string' || typeof key2 !== 'string') return false;
  if (key1.length !== key2.length) return false;

  let result = 0;
  for (let i = 0; i < key1.length; i++) {
    result |= key1.charCodeAt(i) ^ key2.charCodeAt(i);
  }
  return result === 0;
};
```

## 3. 加密流程解析

### 3.1 数据加密完整流程

#### GCM模式加密流程（`CryptoService.encrypt`）

```typescript
static encrypt(data: string, key: Buffer, algorithm: string = 'aes-256-gcm'): string {
  // 1. 输入验证
  this.validateData(data);
  this.validateKey(key, algorithm);

  // 2. 生成IV（GCM模式推荐12字节）
  const iv = crypto.randomFillSync(new Uint8Array(12));

  // 3. 创建加密器
  const cipher = crypto.createCipheriv(algorithm, key, iv);

  // 4. 执行加密
  let encrypted = cipher.update(data, 'utf8', 'base64');
  encrypted += cipher.final('base64');

  // 5. 获取GCM认证标签
  const authTag = cipher.getAuthTag();

  // 6. 返回格式: iv:authTag:encryptedContent
  return `${Buffer.from(iv).toString('base64')}:${authTag.toString('base64')}:${encrypted}`;
}
```

#### 加密数据格式

```
┌─────────────────────────────────────────────────────────────┐
│                    加密数据格式 (GCM)                         │
├─────────────────────────────────────────────────────────────┤
│  iv:authTag:encryptedContent                                 │
│  │    │       └─ Base64编码的加密内容                          │
│  │    └─ Base64编码的128位认证标签                             │
│  └─ Base64编码的12字节初始化向量                               │
└─────────────────────────────────────────────────────────────┘

示例：
"dGVzdElWMTIz:YXV0aFRhZzEyMw==:ZW5jcnlwdGVkQ29udGVudA=="
```

### 3.2 数据解密完整流程

#### GCM模式解密流程（`CryptoService.decrypt`）

```typescript
static decrypt(encryptedData: string, key: Buffer, algorithm: string = 'aes-256-gcm'): string {
  // 1. 解析加密数据格式
  const parts = encryptedData.split(':');
  if (parts.length !== 3) {
    throw new CryptoError('加密数据格式错误', CryptoErrorCode.INVALID_ENCRYPTED_FORMAT);
  }

  const [ivBase64, authTagBase64, encryptedContent] = parts;

  // 2. 解析IV
  const iv = Buffer.from(ivBase64, 'base64');
  if (iv.length !== 12) {
    throw new CryptoError('IV长度错误', CryptoErrorCode.INVALID_ENCRYPTED_FORMAT);
  }

  // 3. 解析认证标签
  const authTag = Buffer.from(authTagBase64, 'base64');

  // 4. 创建解密器
  const decipher = crypto.createDecipheriv(algorithm, key, iv);

  // 5. 设置认证标签（GCM模式必须）
  decipher.setAuthTag(authTag as any);

  // 6. 执行解密
  let decrypted = decipher.update(encryptedContent, 'base64', 'utf8');
  decrypted += decipher.final('utf8');

  return decrypted;
}
```

### 3.3 IV（初始化向量）管理

#### IV生成策略

- **GCM模式**：使用12字节IV（推荐值，平衡安全性和性能）
- **CBC模式**：使用16字节IV（块大小）
- **随机生成**：每次加密使用 `crypto.randomFillSync` 生成新IV
- **永不重复**：确保相同明文加密后产生不同密文

#### IV存储

```typescript
// 加密后解析存储
const encryptionResult = this.parseEncryptedContent(encryptedContent);

return {
  ...plainNote,
  content: encryptionResult.encryptedContent,
  iv: encryptionResult.iv, // 存储IV
  auth_tag: encryptionResult.authTag, // 存储认证标签（GCM）
  is_encrypted: 1,
};
```

### 3.4 认证标签（Auth Tag）应用

#### GCM模式认证机制

```typescript
// 加密时获取认证标签
const authTag = cipher.getAuthTag();

// 解密时验证认证标签
decipher.setAuthTag(authTag as any);

// 如果数据被篡改，final()会抛出错误

```

#### 安全特性

- **完整性验证**：检测密文是否被篡改
- **认证加密**：同时提供机密性和完整性
- **防重放攻击**：结合IV使用，每次加密结果唯一

## 6. 安全特性实现

### 6.1 认证加密（Authenticated Encryption）

#### GCM模式实现

```typescript
// 加密时生成认证标签
const cipher = crypto.createCipheriv(algorithm, key, iv);
let encrypted = cipher.update(data, 'utf8', 'base64');
encrypted += cipher.final('base64');
const authTag = cipher.getAuthTag(); // 获取128位认证标签

// 解密时验证认证标签
const decipher = crypto.createDecipheriv(algorithm, key, iv);
decipher.setAuthTag(authTag as any); // 设置认证标签
let decrypted = decipher.update(encryptedContent, 'base64', 'utf8');
decrypted += decipher.final('utf8'); // 如果数据被篡改，此处会抛出错误
```

#### 安全特性

- **机密性**：AES加密保护数据内容
- **完整性**：Auth Tag验证数据未被篡改
- **真实性**：确保数据来自合法来源

### 6.2 时序攻击防护

#### 安全密钥比较

```typescript
export const secureCompareKeys = (key1: string, key2: string): boolean => {
  if (typeof key1 !== 'string' || typeof key2 !== 'string') return false;
  if (key1.length !== key2.length) return false;

  let result = 0;
  // 使用按位异或，确保比较时间恒定
  for (let i = 0; i < key1.length; i++) {
    result |= key1.charCodeAt(i) ^ key2.charCodeAt(i);
  }
  return result === 0;
};
```

### 6.3 密钥长度验证

```typescript
private static validateKey(key: Buffer, algorithm: string = 'aes-256-cbc'): void {
  if (!key || !(key instanceof Buffer)) {
    throw new CryptoError('密钥必须是有效的Buffer对象', CryptoErrorCode.INVALID_KEY);
  }
  if (key.length === 0) {
    throw new CryptoError('密钥不能为空', CryptoErrorCode.INVALID_KEY);
  }
  if (!this.isValidKeyLength(key.length, algorithm)) {
    throw new CryptoError(
      `密钥长度${key.length}字节与算法${algorithm}不匹配`,
      CryptoErrorCode.INVALID_KEY,
    );
  }
}
```

### 6.4 数据验证机制

#### 输入数据验证

```typescript
private static validateData(data: string, allowEmpty: boolean = false): void {
  if (data === null || data === undefined) {
    throw new CryptoError('数据不能为null或undefined', CryptoErrorCode.INVALID_DATA);
  }
  if (typeof data !== 'string') {
    throw new CryptoError('数据必须是字符串类型', CryptoErrorCode.INVALID_DATA);
  }
  if (!allowEmpty && data.length === 0) {
    throw new CryptoError('数据不能为空字符串', CryptoErrorCode.INVALID_DATA);
  }
  if (data.length > MAX_DATA_LENGTH) {  // 10MB限制
    throw new CryptoError(
      `数据长度超过最大限制(${MAX_DATA_LENGTH}字节)`,
      CryptoErrorCode.INVALID_DATA,
    );
  }
}
```

#### 加密数据格式验证

```typescript
export const validateEncryptedData = (data: string): boolean => {
  if (!data || typeof data !== 'string') return false;

  const parts = data.split(':');
  if (parts.length !== 2 && parts.length !== 3) return false; // 支持CBC和GCM格式

  const [ivBase64, encryptedContent] = parts;

  // 验证IV部分
  if (!ivBase64 || !isValidBase64(ivBase64)) return false;
  try {
    const iv = Buffer.from(ivBase64, 'base64');
    if (iv.length !== 12 && iv.length !== 16) return false; // GCM=12, CBC=16
  } catch {
    return false;
  }

  // 验证加密内容部分
  if (!encryptedContent || encryptedContent.length === 0) return false;

  return true;
};
```

### 6.5 错误处理中的安全信息泄露防护

#### 错误分类

```typescript
export enum CryptoErrorCode {
  INVALID_KEY = 'INVALID_KEY',
  INVALID_DATA = 'INVALID_DATA',
  INVALID_ALGORITHM = 'INVALID_ALGORITHM',
  ENCRYPTION_FAILED = 'ENCRYPTION_FAILED',
  DECRYPTION_FAILED = 'DECRYPTION_FAILED',
  INVALID_ENCRYPTED_FORMAT = 'INVALID_ENCRYPTED_FORMAT',
  KEY_GENERATION_FAILED = 'KEY_GENERATION_FAILED',
}

export class CryptoError extends Error {
  constructor(
    message: string,
    public readonly code: CryptoErrorCode,
    public readonly originalError?: Error,
  ) {
    super(message);
    this.name = 'CryptoError';
  }
}
```

#### 安全错误处理原则

- 不向用户暴露内部实现细节
- 错误消息不包含敏感信息（如密钥、IV等）
- 原始错误仅用于日志记录，不传递给上层

### 6.6 防篡改措施

#### 数据库层面

- 使用 `is_encrypted` 标记区分加密/非加密笔记
- 加密笔记必须包含 `iv` 字段
- GCM模式加密笔记必须包含 `auth_tag` 字段

#### 应用层面

- 解密时验证数据格式完整性
- 使用认证标签验证数据未被篡改
- 密钥不匹配时拒绝解密（不解密为乱码）

## 8. 总结与建议

n### 8.1 架构优势

1. **分层清晰**：CryptoService、EncryptedNoteService、TransparentCryptoService 三层架构职责明确
2. **算法先进**：默认使用AES-256-GCM认证加密，兼顾安全性和性能
3. **密钥安全**：双层存储机制（SecureStore优先，AsyncStorage回退）
4. **透明加密**：用户无感知，内存明文、存储密文
5. **完整验证**：输入验证、格式验证、完整性验证多层防护

### 8.2 安全亮点

1. **认证加密**：GCM模式提供完整性保护，防止数据篡改
2. **时序攻击防护**：secureCompareKeys实现恒定时间比较
3. **IV随机化**：每次加密使用随机IV，防止模式识别
4. **错误处理**：分类错误代码，避免信息泄露
5. **密钥管理**：版本控制、自动备份、安全导入导出

### 8.3 改进建议

#### 短期改进

1. **增加密钥轮换机制**：定期自动更换加密密钥
2. **完善审计日志**：记录密钥操作和加密事件
3. **增强测试覆盖**：增加并发测试和性能测试

#### 中期改进

1. **支持硬件加密**：利用设备TEE（可信执行环境）
2. **实现密钥派生**：使用PBKDF2或Argon2替代直接密钥存储
3. **添加生物识别**：支持指纹/面容识别解锁密钥

#### 长期规划

1. **端到端加密**：实现服务器也无法解密的E2EE方案
2. **多设备密钥同步**：安全的跨设备密钥同步机制
3. **量子安全算法**：关注后量子密码学发展

### 8.4 最佳实践总结

1. **始终使用GCM模式**：除非兼容性要求，否则优先使用AES-GCM
2. **密钥长度选择**：使用32字节（256位）密钥获得最高安全性
3. **IV管理**：每次加密生成新IV，与密文一起存储
4. **错误处理**：使用特定错误类型，避免泄露敏感信息
5. **密钥存储**：优先使用硬件安全存储，做好回退方案
